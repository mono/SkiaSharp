Version 4.154.0

Documented APIs and GPU reliability · Released October 12, 2026 · NuGet · GitHub Release

API changes · SkiaSharp API diff · HarfBuzzSharp API diff

Highlights

SkiaSharp 4.154.0 packages compiler XML documentation and improves GPU failure handling on Skia m154. This release also synchronizes HarfBuzz enum values and Uno WebAssembly native assets. Built-in RAW/DNG decoding is no longer available.

Breaking Changes

  • Decode RAW and DNG images outside SkiaSharp — Built-in DNG development and PIEX-based embedded RAW-preview decoding are disabled. Use an external RAW decoder and pass decoded pixels or an extracted JPEG to SkiaSharp. Standalone JPEG decoding remains available; SKEncodedImageFormat.Dng is retained for compatibility but does not indicate codec support. (#5190)
  • Use the corrected HarfBuzz combining-class name — Replace UnicodeCombiningClass.CCC133 with CCC132. The numeric value remains 132, but there is no compatibility alias for the old name. (#5057)
  • Combine concrete HarfBuzz glyph flags — GlyphFlags.Defined is removed. Combine the concrete flags needed by your application instead of relying on an aggregate mask of all flags known to a particular HarfBuzz version. (#5057)
  • Stop referencing generated Blazor imports — The generated SkiaSharp.Views.Blazor._Imports type is no longer shipped after the canvas components moved to source-controlled C#. Remove direct references to this generated imports artifact and reference the canvas components instead; existing canvas markup and rendering behavior are unchanged. (#5064)

Engine

  • Skia m154 — Updates the renderer to milestone 154 while preserving the existing C exports and managed P/Invoke surface. Native HarfBuzz remains 14.2.1; its .400 package revision distinguishes this milestone's package set. (#4945)

API Surface

  • Packaged IntelliSense documentation — Ships source-authored compiler XML beside implementation and reference assemblies, with matching documentation in lib and ref assets. Packages with reference assemblies are checked for missing or mismatched XML sidecars. (#5064, #5066, #5080)
  • HarfBuzz enum coverage — Synchronizes supported buffer, cluster, glyph and baseline-tag values with the bundled HarfBuzz 14.2.1 source, without introducing new managed types or exposing callback-heavy native API families. (#5057)

Bug Fixes

  • GPU text and failed-work handling — Corrects partial glyph-atlas generation tracking and propagates failed render tasks and prerequisite flushes through existing failure contracts. Checked GPU-buffer upload failures reject affected draws, and failed flushes evict uniquely held cache entries that could reference uninitialized textures. (#5054, #5114, #5253)
  • Uno WebAssembly native assets — The Uno WinUI views package depends on matching HarfBuzz WebAssembly assets, preventing link failures caused by pairing current managed imports with Uno's older implicit native archive. (#5057)
  • Windows HarfBuzz BinSkim compatibility — Corrects the BA2007 disabled-compiler-warnings error in libHarfBuzzSharp.dll on x86, x64 and ARM64 without changing its native exports. — ❤️ @azchohfi (#5111)

HarfBuzzSharp 14.2.1.400

Synchronizes supported enum values with HarfBuzz 14.2.1, including the CCC133-to-CCC132 rename and removal of GlyphFlags.Defined. Also fixes Windows BinSkim BA2007 compatibility, matches Uno WebAssembly native assets and supplies compiler XML documentation.
