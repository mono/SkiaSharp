Version 4.151.0

Faster raster and text paths · Released July 30, 2026 · NuGet · GitHub Release

API changes · SkiaSharp API diff · HarfBuzzSharp API diff

Highlights

SkiaSharp 4.151.0 restores CPU bitmap rendering performance and reduces overhead in color and text operations. The Skia m151 release also adds span-based parsing, fixes intermediate image cleanup and aligns WebAssembly native libraries with .NET 11.

Breaking Changes

  • Remove whitespace after the color prefix — SKColor.Parse and TryParse now reject whitespace immediately after '#' in six- and eight-digit input. Remove that whitespace before parsing; case-insensitive hexadecimal input and surrounding whitespace remain supported. (#4345)

Engine

  • Skia m151 — Updates the bundled renderer to milestone 151 without changing the existing C API or managed binding surface in the engine update. (#4294)

API Surface

  • Parse directly from spans — Adds ReadOnlySpan overloads for SKColor.Parse/TryParse and SKFourByteTag.Parse, avoiding substring creation and unnecessary parsing work. (#4345, #4396)

Bug Fixes

  • CPU bitmap drawing performance restored — Restores the optimized shader-context path for scaled and tiled CPU bitmap draws, addressing high CPU use, dropped frames and flicker in affected canvas applications. (#4428)
  • Ganesh stencil and resolve handling — Corrects stencil-clear coordinates, ensures stencil is cleared when preserving contents, and unwinds dirty tracking when a resolve task fails. (#4443, #4489)
  • Malformed native text cleanup — Corrects destruction ordering when corrupt Slug data fails to deserialize, avoiding reads and frees through already released backing memory. (#4382)

Lifecycle & Internals

  • Prompt subset-image cleanup — SKImage.FromEncodedData(SKData, SKRectI) disposes the intermediate full image when Subset returns a different instance, while preserving same-instance results and decoded pixels. (#3997)
  • Lower color and shaping overhead — Moves single-color conversion and premultiplication math into managed code with native-equivalent results. SKShaper reads glyph buffers through zero-copy spans instead of allocating two temporary arrays. (#4370, #4385, #4388)

Platform

  • Matching .NET 11 WebAssembly libraries — Ships Emscripten 5.0.6 variants for .NET 11 and compiles them with the new exception-handling model, correcting link failures and browser startup failures. .NET 8, 9 and 10 keep their existing native mappings. — ❤️ @ramezgerges (#4459, #4487)

HarfBuzzSharp 14.2.1

SkiaSharp.HarfBuzz 4.151.0 depends on HarfBuzzSharp 14.2.1. The span-based Tag.Parse overload collected in this development line first shipped in HarfBuzzSharp 14.2.1.102, co-shipped with SkiaSharp 4.151.2; it is not present in 4.151.0's default dependency.
