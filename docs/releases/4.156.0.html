Version 4.156.0

GTK4 rendering and platform updates · Released November 9, 2026 · NuGet · GitHub Release

API changes · SkiaSharp API diff · HarfBuzzSharp API diff

Highlights

SkiaSharp 4.156.0 combines Skia m156 with GTK4 GPU drawing, Uno 7 support and font-lifetime fixes. Linux NoDependencies packages regain installed-font discovery, Android continuous rendering follows the display clock, and native updates correct path, clipping and text output. Review the GTK4 coordinate change, Uno migration and higher Apple and Tizen requirements before upgrading.

Breaking Changes

  • Choose GTK4 logical coordinates explicitly — SKDrawingArea now paints in physical pixels by default on high-density displays. Set IgnorePixelScaling=true to retain logical paint coordinates while keeping full-resolution backing pixels. RawInfo remains physical and GTK input coordinates remain logical. (#5249)
  • Migrate Uno views to Uno 7 and .NET 10 — The non-Windows Uno views require Uno 7 and net10.0; pre-Uno 7 WasmShell pipelines are no longer supported. SKSwapChainPanel now derives from Grid, removes RaiseOnUnsupported and uses a CPU canvas with null GRContext. Use SKCanvasElement for Uno GPU drawing and the .NET SDK WASM pipeline. The Windows facade remains ANGLE-backed. (#5377)
  • Raise Apple application deployment targets — SkiaSharp and HarfBuzzSharp native libraries now require macOS 12 or iOS, tvOS and Mac Catalyst 15. Raise application deployment targets to at least those versions, retaining any higher requirement imposed by the managed target or framework. (#5383, #5514)
  • Retarget Tizen applications to Tizen 10 — The new x64 and ARM64 native builds and NativeAssets packages no longer support Tizen 8 or 9. Move applications to net10.0-tizen10.0 and manifest API 10. Building the native libraries from source requires the Tizen 10 SDK and GCC 14.2. (#5235)
  • Pass valid text and data buffer lengths — Encoded text APIs now reject negative byte lengths with ArgumentOutOfRangeException and odd GlyphID byte counts with ArgumentException. Supply complete 16-bit glyph IDs and nonnegative lengths. SKData.CreateCopy(byte[], ulong) also throws ArgumentOutOfRangeException when length exceeds the array; keep the requested length within the source buffer. (#5382, #5429)
  • Use portable Windows runtime identifiers — AnyCPU native-asset selection for SkiaSharp, HarfBuzzSharp and WinUI now uses win-x86, win-x64 and win-arm64 instead of the legacy win10-* branches. Update explicit runtime identifiers accordingly. Explicit-platform and empty-RID selection paths are preserved. (#5551)
  • Rebuild custom WebGPU archives — Newer WebAssembly consumers require libSkiaSharp.a to contain emdawnwebgpu's C++ support. Rebuild custom archives with Graphite enabled; older or GPU-disabled archives do not satisfy this link contract. Matching JavaScript glue remains a consumer link input, and the .NET 8 built-in WebGPU path is retained. (#5316)
  • Pass one encoded unit to GetUnicodeCharacterCode — StringUtilities.GetUnicodeCharacterCode now validates encoded byte width. Pass ASCII for UTF-8, a BMP character for UTF-16 or one Unicode code point for UTF-32; use UTF-32 for supplementary characters. Previously accepted multi-character UTF-32 strings are rejected instead of silently returning the first character's code. (#5506)
  • Use supported Windows native targets — The fork-specific WinRT native target is retired. Move custom native builds using that target to a supported desktop Windows, WinUI/Windows App SDK or NanoServer path. (#5382)

Engine

  • Skia milestone 156 — Updates the bundled renderer to m156 without adding managed bindings. HarfBuzzSharp package revision 14.4.0.100 accompanies this milestone while native HarfBuzz remains 14.4.0. (#5247)

API Surface

  • Native GTK4 GPU canvas — Adds SKGLArea with PaintSurface, CanvasSize, GRContext, EnableRenderLoop and IgnorePixelScaling. GTK owns the GL context; use QueueRender to invalidate. Manually bundled GTK runtimes must include libepoxy. Raster views also correct Cairo pixel-storage disposal order and dirty notification. (#5249)

Bug Fixes

  • Installed fonts work again without fontconfig — Linux NoDependencies packages restore directory-backed default font discovery, normally under /usr/share/fonts/. Installed fonts can resolve by family again, avoiding the empty-typeface and SKShaper construction failures caused by the former fallback. — ❤️ @ramezgerges (#5086)
  • More reliable path and GPU text rendering — Corrects clipped convex-path rasterization, region storage for subdivided conics, reflected hairline caps, glyph bounds and atlas selection. GPU fixes also cover glyph replay validation, Graphite clipping and paint keys, GLES texture uploads, and alpha-to-RGBx readback stride. (#5500, #5517, #5575, #5617, #5624, #5631, #5671)
  • Runtime shaders fail safely — Rejects overflowing shader slot counts and invalid runtime-effect types. Failed shader-pipeline construction no longer leaves executable partial branches, and transformed child failures propagate instead of executing an incomplete pipeline. (#5489, #5517)
  • Android automatic frames follow display refresh — Continuous texture rendering, including MAUI SKGLView.HasRenderLoop, uses Choreographer pulses instead of unbounded swap throughput. Painting stays on the GL worker; explicit RequestRender calls and lifecycle work remain independent of automatic pacing. (#5345)
  • Linux shaping avoids mixed HarfBuzz implementations — Binds internal calls to the bundled HarfBuzz functions on Linux, preventing system HarfBuzz loaded by GTK from redirecting those calls to an incompatible implementation. This addresses load-order-dependent crashes without changing exported functions or managed signatures. — ❤️ @VirgilMing (#5352)
  • Unicode helpers respect encoded unit width — StringUtilities.GetUnicodeCharacterCode decodes one unit of the requested encoding: ASCII for UTF-8, a BMP unit for UTF-16, or a full code point for UTF-32. StringUtilities.GetString now reports ArgumentNullException, rather than NullReferenceException, for null byte arrays. (#5506)

Lifecycle & Internals

  • Custom font and stream references released — DWriteCore custom-font data is released after the last dependent typeface clone is disposed. Disposing SKFrontBufferedManagedStream releases its reference to a borrowed stream without disposing that stream; the caller still owns disposal. WinUI EGL teardown also releases the native window held by a current surface. (#5577, #5327, #5551)
  • Callback ABIs match native boolean widths — Skia callbacks use one-byte native booleans and HarfBuzz callbacks use four-byte hb_bool_t values, while public managed delegates remain bool. This corrects callback interoperability, including false returns, without changing public signatures. (#5479)
  • Native callback and resource ownership corrected — Retains the OpenGL module behind cached WGL pointers and corrects optional stream callbacks and XPS COM ownership. (#5382)
  • Managed image copies avoid an intermediate allocation — Valid managed pixel buffers are copied directly to raster images without an intermediate SKData allocation. Invalid-input behavior remains unchanged. (#5052)

Platform

  • WebAssembly archives match the target framework — SkiaSharp and HarfBuzzSharp select Emscripten 3.1.34 for .NET 8, 3.1.56 for .NET 9/10 and 6.0.2 for .NET 11+. WebGPU C++ support is now inside libSkiaSharp.a, avoiding C++ flags on application C sources. Consumers need matching rebuilt archives; the .NET 8 built-in WebGPU path is retained. — ❤️ @ramezgerges (#5306, #5316)
  • Updated Windows rendering dependencies — WinUI's bundled ANGLE advances to chromium/8118, with PDB names aligned to the shipped DLLs. Windows library dependencies align with MAUI 9 and 10; these changes do not raise the declared Windows runtime minimum. (#5321, #5390)

HarfBuzzSharp 14.4.0.100

HarfBuzzSharp 14.4.0.100 retains native HarfBuzz 14.4.0. It corrects callback boolean widths, reduces allocations in UTF-32 input and feature-string conversion, and shares the Apple, Tizen, Windows RID and .NET 11 WASM alignment described above.
