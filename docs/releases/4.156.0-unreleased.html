Version 4.156.0 (Unreleased)

More efficient rendering and interop

Highlights

SkiaSharp 4.156.0 improves browser WebGPU packaging, Android texture rendering, and managed graphics and text-shaping performance. WebGPU browser applications can link against the packaged native archive without compiling its C++ support themselves. Android texture rendering now follows display refresh, while image copying and HarfBuzz text shaping avoid unnecessary managed and native allocations.

Breaking Changes

None in this preview line.

Platform

  • WebGPU support is packaged with browser native assets — The WebGPU C++ support is now built into libSkiaSharp.a, so browser applications no longer compile it during their final link and C projects avoid incompatible C++ compiler flags. — ❤️ @ramezgerges (#5316)

Bug Fixes

  • Android texture rendering follows the display clock — Continuous Android GL texture rendering is paced by display refresh rather than buffer-swap throughput, reducing unnecessary paint callbacks while preserving explicit render requests and lifecycle behavior. (#5345)
  • Front-buffered managed streams no longer retain data unnecessarily — Corrects stream retention so front-buffered managed streams can release data when it is no longer needed. (#5327)

Lifecycle & Internals

  • Image pixel copies avoid an intermediate allocation — Managed pixel buffers that can be copied directly now avoid creating an intermediate SKData instance while preserving existing validation behavior. (#5052)
  • Text shaping reduces temporary allocations — HarfBuzz UTF-32 buffer input and feature-string formatting reuse managed storage where possible, reducing allocation overhead without changing encoded text or feature decoding. (#5060, #5230)
