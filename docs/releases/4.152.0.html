Version 4.152.0

Graphite and asynchronous readback · Released September 5, 2026 · NuGet · GitHub Release

API changes · SkiaSharp API diff · HarfBuzzSharp API diff

Highlights

SkiaSharp 4.152.0 introduces Graphite GPU bindings and backend-neutral asynchronous pixel readback. Built on Skia m152, this release adds Silk.NET Vulkan helpers and explicit font loading on Nano Server, while correcting source lifetimes and reducing text and data-copy overhead.

Breaking Changes

None in this release.

Engine

  • Skia m152 — Updates the renderer to milestone 152 and VulkanMemoryAllocator to 3.4.0, preserving the allocator fallback used by SkiaSharp callers. (#4651)

API Surface

  • Graphite GPU backend — Adds contexts, recorders, recordings and texture wrappers for Vulkan, Metal and Dawn, including browser WebGPU. Graphite uses explicit record, snap, insert and submit operations; existing Ganesh APIs remain unchanged. — ❤️ @ramezgerges (#3968)
  • Asynchronous pixel readback — Adds RequestReadPixels to SKImage and SKSurface. Results are callback-scoped: copy data inside the callback to retain it, and handle a null result on failure. Ganesh completion requires submission and CheckAsyncWorkCompletion; Graphite surfaces use asynchronous rather than synchronous readback. — ❤️ @ramezgerges (#4545, #3968)
  • Silk.NET Vulkan integration — Adds SkiaSharp.Vulkan.Silk.NET with typed backend-context and extension helpers, and makes the GRVkExtensions constructor public. The existing SharpVk package remains available; package production now includes the Silk.NET helper. (#4527, #4841)

Lifecycle & Internals

  • Keep borrowed native sources alive — Region iterators retain their source region, and pixmap subsets and With* results retain the ultimate pixel owner, preventing premature finalization while derived objects are still in use. (#4355, #4558)
  • Deterministic resource cleanup — Releases the previous uniform buffer on Reset, disposes copied stream assets when HarfBuzz blobs release them, and frees raster pixel storage when image creation fails. Native cached-data destruction now releases its mutex guard before deleting the owner. (#4783, #4710, #4455, #4925)
  • Less copying and allocation — Font.Shape avoids copying an existing feature array, tag formatting avoids boxed characters, and text marshalling and uniform lookup construction allocate less. SKData.SaveTo writes native spans directly on span-capable targets; .NET Framework and netstandard2.0 retain buffered copying. (#4690, #4752, #4498, #4512, #4550, #4630)

Bug Fixes

  • Do not read stale GPU textures — Ganesh readbacks no longer return stale texture data when prerequisite render tasks fail to flush; additional font-rendering and Ganesh stability corrections are included. (#4538, #4568)

Platform

  • Explicit Nano Server font loading — The Nano Server native build uses FreeType so fonts loaded from files, streams or data can render. It still has no system font manager: load a typeface explicitly rather than relying on the default font. Normal Windows builds retain DirectWrite. — ❤️ @jeffska (#4280)
  • Native debugging assets — Produces separate Apple symbol packages with complete dSYM bundles for SkiaSharp and HarfBuzzSharp, without adding symbols to customer runtime packages. Android libraries retain matching build IDs and split-debug identities. (#4846, #4843)

HarfBuzzSharp 14.2.1.200

Font.Shape avoids a defensive feature-array copy, and Tag.ToString avoids character boxing. Apple symbol packages and deterministic Android debug identities improve native diagnostics; NuGet READMEs provide package-specific guidance.
