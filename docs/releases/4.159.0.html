Version 4.159.0

Programmable meshes and image comparisons · NuGet (prerelease)

Highlights

SkiaSharp 4.159 previews Skia m159 with programmable GPU meshes and an experimental image-comparison package. This line also corrects Windows image-decoding crashes, runtime-effect uniform initialization, and Apple device frameworks. WebAssembly now requires .NET 9 or later, and Linux x86 native assets are no longer packaged.

Breaking Changes

  • Move WebAssembly apps to .NET 9 or later — SkiaSharp and HarfBuzzSharp no longer provide .NET 8 WebAssembly native assets; unsupported WASM targets are rejected during the build. Retarget WebAssembly apps to .NET 9 or later and use the matching runtime assets. Non-WebAssembly .NET 8 support is unchanged. (#5700)
  • Move Linux x86 deployments to a supported architecture — Linux x86 native assets are no longer built or included in NuGet packages for SkiaSharp and HarfBuzzSharp. Move 32-bit Linux deployments to a supported architecture, such as x64 or ARM64, before upgrading. (#5784)

Engine

  • Skia m159 and servicing updates — Updates the native renderer to m159, bringing WebAssembly SIMD CPU rasterization and Windows font-loading improvements. Subsequent m159 fixes harden mask-filtered glyph reloads, correct image-filter cache-key equality, and work around Imagination Vulkan descriptor-allocation failures without changing the milestone. (#5685, #5741, #5769, #5841)

API Surface

  • Programmable GPU meshes — SKMeshSpecification, indexed and non-indexed mesh builders, vertex/index buffers and SKCanvas.DrawMesh expose custom SkSL vertex and fragment programs. Built meshes retain their native dependencies after the source wrappers are disposed. Drawing requires a GPU-backed surface; raster drawing is a no-op. (#5760)
  • Experimental image-comparison package — SkiaSharp.Testing adds SKImageComparison for images, bitmaps and pixmaps, with channel tolerances, masks, mismatch budgets, error metrics and difference images. The separate package is experimental: acknowledge diagnostic SKIA4001 to opt in. Returned comparison results retain no native handles; difference images belong to the caller. (#5293)

Bug Fixes

  • Windows x64 image error recovery — Fixes process termination during libjpeg/libpng longjmp error recovery in x64 clang-built natives, including malformed JPEG decoding and PDF output with lazy non-JPEG images. Control Flow Guard remains enabled; x86, ARM64 and MSVC builds are unchanged. — ❤️ @SimonCropp (#5827)
  • Zero-initialized runtime-effect uniforms — New SKRuntimeEffectUniforms blocks now start at zero rather than containing leftover memory. Reset clears the existing buffer in place, avoiding a native buffer and managed wrapper allocation on each call; the fix also covers mesh uniforms. — ❤️ @taublast (#5843)
  • Filtered texture edges and Tizen blurs — Ganesh sampling clamps slightly inside texture subsets to avoid undefined exterior texels; CPU and Graphite sampling are unchanged. Tizen now applies its intended CPU blur-path selection when compiling Skia. Texture-edge pixels and Tizen blur output or performance may differ; Tizen performance was not measured. (#5679)
  • Correct iOS and tvOS device frameworks — SkiaSharp and HarfBuzzSharp device frameworks now contain only arm64 device binaries and device platform metadata, avoiding the simulator slices and metadata that could trigger App Store error ITMS-90087. Separate simulator frameworks and their x64/arm64 slices remain available. — ❤️ @kdpkke (#5649)
  • Trim-safe MAUI SKGLView binding — Replaces the string-path Window binding with a typed expression, removing the trimming warning when constructing SKGLView in trimmed MAUI apps without changing the binding's intended behavior. — ❤️ @bhall-ctre (#5320)

HarfBuzzSharp 15.0.0.100

HarfBuzzSharp now requires .NET 9 or later for WebAssembly and no longer packages Linux x86 native assets. Its iOS/tvOS device frameworks now contain only arm64 device slices and the correct device metadata, while separate simulator frameworks remain available.
