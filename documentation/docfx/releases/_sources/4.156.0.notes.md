# Manual additions for 4.156.0

> Maintainer-authored consumer notes for the m155-to-m156 update, especially compatibility
> changes that managed API diffs cannot show. Preserve these when regenerating RC/stable notes.
>
> Shipment scope matters: the first section is present in `v4.156.0-preview.1.26512.10`.
> The second section describes later changes merged into main, not changes shipped in Preview 1.
> Include those later notes only when the page's collected PRs include the referenced changes;
> do not backdate them into Preview 1 or its exact GitHub Release summary.

## Present in Preview 1

### Tizen applications now require Tizen 10 (#5235)

The managed minimum supported Tizen version rises from 6.5 to 10.0, and the older .NET 6/.NET 9
Tizen 8 targets are removed. Retarget applications to the supported Tizen 10 target and deploy
on Tizen 10 or later; keep an earlier compatible package version for older devices. The
Tizen 10/GCC 14.2 toolchain change is a native-build prerequisite, not a new requirement for
consumers on other platforms.

### GTK4 gains GPU drawing and changes high-DPI coordinates (#5249)

`SkiaSharp.Views.Gtk4` adds `SKGLArea`, with `PaintSurface`, `GRContext`, and `EnableRenderLoop`
for GPU rendering. It requires a working GTK OpenGL/OpenGL ES context; it has no software fallback.

`SKDrawingArea` now allocates its backing surface at the display scale rather than the logical
widget size. On high-DPI displays, the default `CanvasSize` and paint-event `Info` therefore
describe more pixels than before. Set `IgnorePixelScaling = true` to draw in logical coordinates;
the canvas is scaled automatically, `Info` is logical, and `RawInfo` remains physical.
GTK input coordinates are logical: use that mode or convert input coordinates to backing pixels,
and remove any application scaling that would otherwise be applied twice.

### Linux NoDependencies discovers installed fonts again (#5086)

`SkiaSharp.NativeAssets.Linux.NoDependencies` scans `/usr/share/fonts/` instead of returning an
empty font manager. Install fonts there for system-font discovery, or load a bundled typeface
explicitly when deterministic font selection matters. This does not add a fontconfig dependency.

### Engine and WebAssembly assets (#5247, #5306)

The native engine moves to Skia m156. WebAssembly native-asset selection distinguishes .NET 9/10
assets from the Emscripten 6.0.2 assets used by .NET 11 targets. HarfBuzzSharp's m156 package
revision is `14.4.0.100`; the bundled HarfBuzz engine remains 14.4.0.

## Merged after Preview 1

### Apple deployment minimums increase (#5383)

For both SkiaSharp and HarfBuzzSharp, native iOS/tvOS minimums rise from 11.0 to 14.0, native
Mac Catalyst from 13.1 to 14.0, and Intel macOS from 10.13 to 11.0. ARM64 macOS already required
11.0. Managed iOS/tvOS targets raise their minimum from 12.2 to 14.0; existing managed
Mac Catalyst 15.0 and macOS 12.0 minimums remain unchanged.

Raise application deployment targets to at least the highest minimum required by the native
assets, managed integration, and application framework. In particular, the native Catalyst 14.0
floor does not lower the managed requirement to 14.0. Keep an earlier compatible package version
for applications that must run on older operating systems.

### Uno Platform 7 changes integration and GPU assumptions (#5377)

`SkiaSharp.Views.Uno.WinUI` now supports Uno Platform 7 and .NET 10 or later, replacing the
Uno.WinUI 5.2.175 dependency with 7.0.0-dev.2333. The old platform-specific assemblies and
`uno-runtime` layout are replaced by the shared Uno integration. Upgrade the application to
Uno 7/.NET 10+; use Uno.Sdk's native-asset integration rather than copying the old runtime layout.
This does not raise the minimum .NET version of every SkiaSharp package.

On non-Windows Uno targets, `SKSwapChainPanel` now renders on the CPU and `GRContext` returns
`null`; its GL-shaped paint event does not imply a GPU-backed surface. Use Uno's `SKCanvasElement`
when GPU rendering is required, and remove assumptions that the panel supplies a usable GL
framebuffer or context. Windows App SDK targets continue to use the Windows GPU control.

### Android continuous rendering is display-paced (#5345)

`GLTextureView` and `SKGLTextureView` continuous rendering follows display frame callbacks while
the view has a drawable surface and is not paused. Missed frame requests are coalesced rather
than queued. Do not use paint callback counts as a fixed-rate simulation clock; use elapsed time
for animation. Render-on-demand still uses `RequestRender()`, and surface creation, resizing,
and resuming may independently request a frame.

### Data validation and stream ownership fixes (#5429, #5327)

`SKData.CreateCopy(byte[], ulong)` now throws `ArgumentOutOfRangeException` when the requested
length exceeds the array. Pass a length within the source array instead of relying on an
out-of-bounds native read. Internal C-string conversion also writes its terminating zero into
correctly sized storage rather than reading one byte beyond the encoded string.

Disposing `SKFrontBufferedManagedStream` releases its reference to a borrowed stream without
disposing that stream. Callers remain responsible for disposing streams they retain ownership of.

### Windows graphics dependencies advance (#5321, #5390)

The bundled ANGLE backend advances from `chromium/6275` to a pinned `chromium/8118` revision,
and `SkiaSharp.Views.WinUI` moves from Windows App SDK 1.4 to 1.7.250909003. Align application
Windows App SDK references with the updated dependency. The WebView2 1.0.3179.45 pin is used by
the native WinUI build; it is not a requirement to add WebView2 to every consuming application.
New Visual Studio requirements apply to building this repository's native libraries, not to
running applications that consume the packages.

### Runtime fixes and allocation reductions (#5052, #5060, #5230, #5352, #5316, #5500)

Valid `SKImage.FromPixelCopy` array/span inputs avoid an intermediate `SKData` allocation and
copy. HarfBuzzSharp pools the UTF-32 conversion buffer in `Buffer.AddUtf32(string)` and uses
stack storage for `Feature.ToString()` without changing text conversion or feature formatting.
These managed optimizations do not upgrade the bundled HarfBuzz engine.

Linux HarfBuzzSharp binds its bundled HarfBuzz functions locally to avoid symbol preemption by
another loaded HarfBuzz library. WebAssembly Graphite assets include emdawnwebgpu's `webgpu.cpp`
in the native archive so applications no longer compile that C++ source at final link time.
The m156 Ganesh GL servicing update disables an unsupported BGRA8-as-RGBx texture-upload path.
