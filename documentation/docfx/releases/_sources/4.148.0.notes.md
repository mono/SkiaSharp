# Curated release facts for 4.148.0

4.148.0 is the first stable v4 release and includes the preview-only 4.147
line. The Polish agent should use the **Release-note blurb** fields as editorial
guidance and the remaining fields to verify and explain each claim.

## Security

### Skia core and Ganesh security fixes

**Release-note blurb:** Includes verified Skia fixes for malformed input,
runtime effects, raster pipelines, pixels, SKP/SkSL handling, PathOps, GPU text,
and Ganesh/Vulkan memory safety.

**Evidence:** The shipped m147 fixes include CVE-2026-7353, CVE-2026-7920, and
CVE-2026-7923 ([#4044](https://github.com/mono/SkiaSharp/pull/4044)).
The m148 update includes CVE-2026-5870, CVE-2026-6298, CVE-2026-6364,
CVE-2026-8510, CVE-2026-8579, CVE-2026-9892, CVE-2026-9893,
CVE-2026-9909, CVE-2026-9981, CVE-2026-9983, CVE-2026-9998,
CVE-2026-10009, and CVE-2026-10011
([#4125](https://github.com/mono/SkiaSharp/pull/4125)). Their fix commits were
verified as ancestors of the Skia fork commit shipped by 4.148.0.

**Scope:** Describe these as the verified Skia/Ganesh fixes above, not as “all
Chrome m148 security fixes.” Do not include Graphite, Chromium integration, or
ANGLE disclosures; those paths did not ship through SkiaSharp 4.148.0.

## Breaking changes

### Default font and typeface behavior

**Compatibility:** Behavioral

**Release-note blurb:** Default-constructed fonts now use an empty typeface,
while paint and missing-family fallbacks return explicit default typefaces.

**Affected APIs:** `SKFont`, `SKPaint.Typeface`, `SKPaint.Reset`,
`SKTypeface.FromFamilyName`, `SKTypeface.Default`

#### Previous behavior

- `new SKFont()` stored a null typeface and resolved the platform default when
  measuring or drawing.
- `new SKPaint().Typeface` and `SKPaint.Reset()` exposed null.
- On Android, `SKTypeface.FromFamilyName("missing")` could return null.

#### New behavior

- `new SKFont()` and assigning a null `SKFont.Typeface` produce
  `SKTypeface.Empty`; text measures to zero and does not draw.
- New or reset `SKPaint` instances expose `SKTypeface.Default`.
- Missing Android family names fall back to `SKTypeface.Default`.
- Default resolution uses the managed font manager, avoiding the Android API 36
  startup crash tracked by [#3693](https://github.com/mono/SkiaSharp/issues/3693).

#### Reason

Skia m132 removed lazy default-typeface resolution. SkiaSharp moved default
font lookup into the managed layer
([#3730](https://github.com/mono/SkiaSharp/pull/3730)).

#### Recommended action

Pass the desired typeface explicitly and use the font manager for strict
family matching:

```csharp
var font = new SKFont(SKTypeface.Default);
var missing = SKFontManager.Default.MatchFamily("MissingFont");
```

Use `Typeface.IsEmpty` rather than a null check when detecting an empty font.

### `SKStream.Move(long)` rejects out-of-range offsets

**Compatibility:** Behavioral

**Release-note blurb:** `SKStream.Move(long)` is obsolete and throws for values
that do not fit the native 32-bit offset instead of silently truncating them.

**Affected APIs:** `SKStream.Move(long)`

#### Previous behavior

Offsets outside the 32-bit range were truncated by an unchecked cast.

#### New behavior

Out-of-range offsets throw `OverflowException`, and the overload produces an
obsolete warning ([#3740](https://github.com/mono/SkiaSharp/issues/3740)).

#### Reason

The native stream API accepts a 32-bit offset; silent truncation could seek to
the wrong position.

#### Recommended action

Validate the range and call `Move(int)`.

### Ganesh Vulkan requires Vulkan 1.1

**Compatibility:** Behavioral

**Release-note blurb:** Ganesh Vulkan now requires Vulkan 1.1; attempting to
create a context for Vulkan 1.0 aborts the process instead of returning null.

**Affected APIs:** `GRContext.CreateVulkan`,
`GRVkBackendContext.MaxAPIVersion`

#### Previous behavior

Unsupported Vulkan versions returned a null context, allowing a raster
fallback.

#### New behavior

Upstream commits `0a3150b03b` and `dfea59a30f` require Vulkan 1.1 and make the
minimum-version check fatal
([#4600](https://github.com/mono/SkiaSharp/issues/4600)).

#### Reason

Ganesh now acquires Vulkan 1.1 core entry points unconditionally.

#### Recommended action

Create the instance as Vulkan 1.1 or later and set the backend context to the
same version:

```csharp
const uint Vulkan11 = (1u << 22) | (1u << 12);
appInfo.ApiVersion = Vulkan11;
backendContext.MaxAPIVersion = Vulkan11;
```

Choose another backend before context creation on Vulkan 1.0-only hardware.

### Vulkan backend context fields removed

**Compatibility:** Source and binary

**Release-note blurb:** `GRVkBackendContextNative` removes five legacy fields;
custom Vulkan interop must use the typed extension and feature objects and
manage instance/device ownership itself.

**Affected APIs:** `GRVkBackendContextNative`

#### Previous behavior

The struct exposed `fMinAPIVersion`, `fInstanceVersion`, `fExtensions`,
`fFeatures`, and `fOwnsInstanceAndDevice`.

#### New behavior

Those fields are removed
([#3741](https://github.com/mono/SkiaSharp/issues/3741)).

#### Reason

Skia replaced the legacy fields with typed Vulkan extension and feature
objects and stopped owning the instance/device through the backend context.

#### Recommended action

Delete assignments to removed fields, use `fVkExtensions` and
`fDeviceFeatures` or `fDeviceFeatures2`, and manage Vulkan object ownership
outside the context.

### Vulkan YCbCr conversion layout changed

**Compatibility:** Source and binary

**Release-note blurb:** Vulkan YCbCr conversion info gains a `Components`
field, changing its native layout; the managed type is also renamed to
`GRVkYcbcrConversionInfo`.

**Affected APIs:** `GrVkYcbcrConversionInfo`,
`GRVkYcbcrConversionInfo`, `GRVkYcbcrComponents`,
`GRVkImageInfo.YcbcrConversionInfo`

#### Previous behavior

The conversion info lacked component mapping and used the inconsistent `Gr`
prefix.

#### New behavior

The layout includes `Components`; the generated type uses the `GR` prefix and
the compatibility type loses its former value-equality members
([#4001](https://github.com/mono/SkiaSharp/pull/4001),
[#3741](https://github.com/mono/SkiaSharp/issues/3741)).

#### Reason

Upstream Skia added Vulkan component mapping and replaced its legacy YCbCr
conversion structure.

#### Recommended action

Update type names, initializers, equality code, and any native layout
assumptions. The managed rename and removed equality members also appear in
the generated breaking API diff.
