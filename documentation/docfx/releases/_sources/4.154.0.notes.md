# Manual additions for 4.154.0

> Maintainer-authored notes for the HarfBuzzSharp 14.2.1 update and binding-generation
> changes. These decisions are not fully represented by the generated API diff.

## HarfBuzzSharp generation now follows the bundled native source

HarfBuzzSharp bindings are now generated directly from the HarfBuzz revision pinned by
Skia's `DEPS` file, which is also the source used to build the bundled native library. The
previous workflow generated against an older HarfBuzz checkout and then restored the old
generated file.

The generator excludes unsupported callback-heavy API families and new native types that are
not currently wrapped. This keeps the managed surface focused while allowing ordinary existing
types, enum values, and internal entry points to stay synchronized with HarfBuzz 14.2.1. No new
managed types are introduced by this update.

## Intentional enum changes

### `UnicodeCombiningClass.CCC133` is corrected to `CCC132`

HarfBuzz historically exposed `HB_UNICODE_COMBINING_CLASS_CCC133` with the numeric value `132`.
Upstream corrected the misspelled name to `HB_UNICODE_COMBINING_CLASS_CCC132`; the value remains
`132`. HarfBuzzSharp follows the corrected upstream name rather than retaining a compatibility
alias, so source code using `CCC133` must change to `CCC132`.

### Aggregate `Defined` members are not exposed

HarfBuzz declares three `*_DEFINED` enum constants:

- `HB_BUFFER_FLAG_DEFINED`
- `HB_BUFFER_SERIALIZE_FLAG_DEFINED`
- `HB_GLYPH_FLAG_DEFINED`

These constants are masks formed by OR-ing all flags known to that HarfBuzz release. They do not
represent independent options and no managed API requires callers to pass them. The individual
flags can be combined directly when a mask is needed.

HarfBuzzSharp therefore does not expose these aggregate constants. This avoids adding new
`BufferFlags.Defined` and `SerializeFlag.Defined` members and removes the existing
`GlyphFlags.Defined` member. Code using `GlyphFlags.Defined` should combine the required concrete
flags instead.
