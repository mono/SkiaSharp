# 11–11 — Ship

Phase 10 is a hard prerequisite. Never publish a failing or partially validated update.

## Developer-run delivery

Push the two feature branches without force. Create draft PRs using each repository's complete PR
template:

| Repository | Head | Base |
|---|---|---|
| mono/skia | `{HEAD_BRANCH}` | `{SKIA_BASE_BRANCH}` |
| mono/SkiaSharp | `{HEAD_BRANCH}` | `{BASE_BRANCH}` |

Cross-link the PRs and include:

- Upstream ref and SHA.
- Conflict and fork-patch dispositions.
- Every dependency decision and build-driven revision change.
- C API, generated binding, managed wrapper, and test changes.
- Exact native build and per-host test results.
- Platforms/backends not executed locally.

## Automated delivery

When `SKIA_SYNC_AUTOMATION=1`, the agent must not push branches or create real GitHub objects.
The deterministic workflow post-step owns guarded pushes, complete templates, labels, and
cross-links.

After every gate passes, require these non-empty artifacts:

- `skia-breaking-change-analysis.md`
- `skia-validation-review.md`
- `skia-dependency-decisions.md`
- `skia-dependency-changes.json`
- `skia-fork-patch-audit.md`
- `initial-test-output.txt`
- `test-output.txt`
- `test-exit-code.txt`

Then write `$ARTIFACT_DIR/skia-sync-skia-summary.md` and
`$ARTIFACT_DIR/skia-sync-skiasharp-summary.md`.

Both summaries use the exact headings `## Changes`, `## Testing`, and `## Human review`. Keep the
reports repository-specific; the post-step inserts them into dedicated complete templates. Report
the exact passed/skipped totals for each host. When platform-policy skips exist, say that no
**required** backend was skipped; never claim that no GPU tests were skipped.

Immediately before handoff, rerun the Phase 05 `audit_fork_patches.py` command against the current
mono/skia HEAD with `--validate`. Late build/test fixes to `DEPS`, C shims, or fork files invalidate
earlier patch fingerprints and regenerate `TODO` rows; inspect those final diffs, replace every
`TODO` with evidence-backed dispositions, and rerun until validation passes.

Finally invoke staged `create_pull_request` exactly once through the injected `safeoutputs` CLI.
Use the actual current parent branch, an `[skia-sync] ...` title, and a short body pointing to the
two summary artifacts. This is only the workflow completion signal; it does not create the real
PR. Do not call `noop`: a started automation run either completes this contract or fails.

## Merge sequence

Do not merge without explicit approval.

1. Merge mono/skia first.
2. Fetch the resulting commit on `{SKIA_BASE_BRANCH}`.
3. Update the parent PR's submodule pointer to that branch commit.
4. Wait for parent CI.
5. Merge the parent PR.

Never leave the parent pointing at an orphaned PR-head commit.

## Completion report

Report both PR URLs, upstream SHA, dependency/fork-patch decisions, native and per-host test
results, required-backend coverage, and remaining cross-platform review.
