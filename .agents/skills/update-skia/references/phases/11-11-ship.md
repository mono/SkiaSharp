# 11–11 — Ship

Phase 10 is a hard prerequisite. Never publish a failing or partially validated update.

## Developer-run delivery

Push the two feature branches without force. Create draft PRs using each repository's complete PR
template:

| Repository | Head | Base |
|---|---|---|
| mono/skia | `{HEAD_BRANCH}` | `{SKIA_BASE_BRANCH}` |
| mono/SkiaSharp | `{HEAD_BRANCH}` | `{BASE_BRANCH}` |

Cross-link the PRs and include:

- Upstream ref and SHA.
- Conflict and fork-patch dispositions.
- Every dependency decision and build-driven revision change.
- C API, generated binding, managed wrapper, and test changes.
- Exact native build and per-host test results.
- Platforms/backends not executed locally.

## Automated delivery

When `SKIA_SYNC_AUTOMATION=1`, the agent must not push branches or create real GitHub objects.
The ordinary workflow publishing job owns guarded pushes, complete templates, labels, and
cross-links. The agent job packages committed branches and reports without write credentials.
Both repositories travel as Git bundles, preserving every commit SHA and merge parent.
Never use a PR safe-output or a generated patch to publish the native sync.
The publisher imports the two bundles independently with recursive submodule fetching
disabled: the parent's new gitlink refers to a native commit that is not on GitHub yet.

After every gate passes, complete the summaries and publication status as one terminal
sequence; do not end the run between them. Require these non-empty artifacts:

- `skia-breaking-change-analysis.md`
- `skia-validation-review.md`
- `skia-dependency-decisions.md`
- `skia-dependency-changes.json`
- `skia-fork-patch-audit.md`
- `native-build.log`
- `native-build-exit-code.txt`
- `managed-build.log`
- `managed-build-exit-code.txt`
- `test-output.txt`
- `test-exit-code.txt`

Require all three exit-code files to contain `0`. Do not edit them to bypass a failed command.

Then write `$ARTIFACT_DIR/skia-sync-skia-summary.md` and
`$ARTIFACT_DIR/skia-sync-skiasharp-summary.md`.

Both summaries use the exact headings `## Changes`, `## Testing`, and `## Human review`. Keep the
reports repository-specific; the publishing job inserts them into dedicated complete templates. Report
the exact passed/skipped totals for each host. When platform-policy skips exist, say that no
**required** backend was skipped; never claim that no GPU tests were skipped. Include
`skia-validation-followup.md` when later parent findings exist.

Finally call the registered `noop` tool once with a status message that local validation
is complete and the host publishing job owns delivery. Do not claim that PRs already exist
or that no engineering work was needed. This tool is status reporting only; it must not
produce a Git patch or publish commits. A failed gate must still report failure, not `noop`.

## Merge sequence

Do not merge without explicit approval.

1. Merge mono/skia first.
2. Fetch the resulting commit on `{SKIA_BASE_BRANCH}`.
3. Update the parent PR's submodule pointer to that branch commit.
4. Wait for parent CI.
5. Merge the parent PR.

Never leave the parent pointing at an orphaned PR-head commit.

## Completion report

Report both PR URLs, upstream SHA, dependency/fork-patch decisions, native and per-host test
results, required-backend coverage, and remaining cross-platform review.
