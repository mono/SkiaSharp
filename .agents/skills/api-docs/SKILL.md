# API Documentation

SkiaSharp C# `///` comments are the authoritative public API prose. Author and
review them with the API implementation; compiler XML is generated by managed
builds and is packaged beside the corresponding managed assemblies.

The parent repository does not contain API-reference ECMA/mdoc source, an mdoc
generator, or a `docs` submodule. `mono/SkiaSharp-API-docs` independently
consumes published packages, compiler XML, and `_DocsMedia`; it generates ECMA
output, preserves deferred Uno output, validates, and publishes Microsoft Learn.
Do not edit that repository from this workflow.

## Scope and workflow

1. Resolve the public types and members in scope and read their C# source under
   `binding/` or `source/` before authoring prose. Do not add comments to
   internal implementation details merely because they are emitted in an
   implementation assembly.
2. Add or correct accurate `///` documentation beside every new or changed
   public API. Generated binding `.cs` comments are source-controlled: update
   their generator inputs and run `utils/SkiaSharpGenerator`; never bypass the
   generator with a manual generated-file edit.
3. Follow [`references/patterns.md`](references/patterns.md), verify domain
   facts against [`references/skia-patterns.md`](references/skia-patterns.md),
   and avoid obsolete examples using
   [`references/obsolete-api-map.md`](references/obsolete-api-map.md).
4. Review with [`references/reviewing.md`](references/reviewing.md) and apply
   the severity bar in [`references/checklist.md`](references/checklist.md).
5. Build the changed managed projects. Confirm that compiler XML is produced
   and that the representative package contract includes adjacent XML in both
   `lib/<tfm>` and `ref/<tfm>`. The reference XML is the consumer-visible
   surface; the same compiler XML copy under `lib` is intentional.

## Boundaries

- Do not manually edit compiler-generated XML, ECMA/mdoc files, or generated
  bindings.
- Do not remove valid public comments to defer documentation to another
  repository. Missing or invalid public documentation blocks the API review.
- `_DocsMedia` is versioned source in this repository and is a nonshipping
  build artifact. The external API-docs repository retrieves the matching
  artifact with published packages; it owns consumption and publication.
